# 工况保存问题修复说明

## 📅 日期
2025-10-14

---

## 🐛 问题描述

### 用户反馈
> "现在的问题是无法计算，在添加完工况，到第5步计算时，总会弹出请在步骤四添加工况"

### 问题分析

**现象**:
- 在步骤四添加了工况
- 切换到步骤五运行计算
- 弹出错误提示："请先在步骤四中添加工况"

**原因**:
- 步骤四的 `add_case()`, `delete_selected()`, `clear_cases()`, `batch_add_cases()` 方法只更新了 `self.cases` 列表
- 但没有立即保存到 `self.app.state["cases"]`
- 只有在调用 `validate()` 方法时才保存
- 但是用户可能直接切换步骤，没有触发 `validate()`
- 导致步骤五读取 `self.app.state["cases"]` 时为空

**代码位置**:
- 步骤四：`Step4PT` 类
- 步骤五：`Step5Output.run_simulation()` 方法（第2064-2076行）

---

## ✅ 解决方案

### 修改策略
在每次修改工况列表后，立即保存到 `self.app.state["cases"]`，确保状态同步。

---

```python
def add_case(self):
    """添加工况"""
    try:
        t = int(self.temp_var.get())
        p = float(self.pres_var.get())
    except Exception:
        messagebox.showerror("格式错误", "温度或压力数值不合法")

    self.cases.append({"T": t, "P": p})
    self.refresh_view()
```
```python
    self.update_statistics()

```

## 💡 技术要点

### 状态管理
- **全局状态**: `self.app.state` - 存储所有步骤共享的数据
- **局部状态**: `self.cases` - 步骤四的工况列表
- **同步策略**: 每次修改局部状态后立即同步到全局状态

### 数据同步时机
1. **添加工况**: `add_case()` 方法
2. **删除工况**: `delete_selected()` 方法
3. **清空工况**: `clear_cases()` 方法
4. **批量添加**: `batch_add_cases()` 方法
5. **验证保存**: `validate()` 方法（保留，作为额外保障）

### 为什么需要立即保存
- 用户可能直接点击侧边栏切换步骤，不会触发 `validate()`
- 步骤五读取的是 `self.app.state["cases"]`，不是 `Step4PT.cases`
- 如果不立即保存，两者会不同步
